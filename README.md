# 山海问知：以学习者为中心的考研智能体工作台

依托通识选修课《考研规划与学术能力进阶：AI辅助学习实践》的学习平台。需求以 [山海问知PRD.md](山海问知PRD.md) 为准，按第15章开发顺序推进。

**当前进度：阶段9「体验增强」已完成**（三维山水长卷与降级、液态毛玻璃、动效编排、性能预算、响应式与无障碍）。阶段1—9全部完成。

## 如何运行

### 1. 环境要求

- Node.js **22.16 或更高的 22.x 版本**（后端使用内置 `node:sqlite`，不需要编译原生模块）。**不要用 22.13—22.15**：这几个版本的内置 SQLite 没有编译 FTS5，知识库检索会直接报 `no such module: fts5`，服务起不来。经实测：22.13 不支持，22.16 及以上支持，22.23.3 与 24.11 均支持
- npm（随 Node 一起安装）

### 2. 安装依赖

```bash
npm run install:all
```

### 3. 配置

复制 `.env.example` 为 `.env`，至少修改：

| 变量 | 说明 |
|---|---|
| `SESSION_SECRET` | 会话签名用的随机长字符串 |
| `KEY_ENC_SECRET` | Key 加密保存用的随机串 |
| `TEACHER_ACCOUNTS` | 教师账号，格式 `用户名:密码,用户名:密码` |
| `DEFAULT_INVITE_CODE` | 首次启动时默认班级的邀请码（不填则随机生成并打印在后端日志里） |
| `LLM_BASE_URL` | 中转站的 `/v1` 地址；**暂时没有真实 Key 时填 `mock`**，使用内置模拟模型 |
| `LLM_PLATFORM_KEY` | 平台 Key（也可登录教师后台填写，后台优先） |

开发模式下如果没填 `SESSION_SECRET` / `KEY_ENC_SECRET`，后端会自动生成并保存在 `data/dev-secrets.json`；**正式部署必须在环境变量中配置**，否则拒绝启动。

注释请单独写一行，不要写在值的后面（Node 内置的 `.env` 读取不支持行尾注释）。

### 4. 启动（开发）

开两个终端：

```bash
npm run dev:server
```

```bash
npm run dev:web
```

浏览器打开 <http://localhost:5173>。前端开发服务器会把 `/api` 转发到后端 `http://localhost:3000`。

### 5. 启动（部署）

```bash
npm run build
```

```bash
npm start
```

后端会在同一端口（默认3000）提供前端页面。也可以用根目录的 `Dockerfile` 构建镜像，数据目录 `/app/data` 需要挂载持久化卷。健康检查接口：`GET /api/health`。

### 6. 自测

```bash
npm test
```

对正在运行的应用做端到端演练（先启动后端；脚本会新建一个 `e2e` 开头的测试学号，演练后请删除）：

```bash
node server/scripts/e2e-stage2.mjs
```

### 7. 检索服务（择校工作台用）

| 变量 | 说明 |
|---|---|
| `SEARCH_PROVIDER` | `none`（默认，不联网检索）/ `bocha`（博查中文搜索）/ `relay`（中转站检索模型，预留） |
| `BOCHA_API_KEY` | 选 `bocha` 时填写 |
| `SEARCH_DAILY_LIMIT_PER_USER` | 每人每天检索次数上限，默认30 |

### 邮件提醒（可选）

| 变量 | 说明 |
|---|---|
| `SMTP_HOST` / `SMTP_PORT` | 默认 `smtp.qq.com` / `465` |
| `SMTP_USER` | 发件用的 QQ 邮箱 |
| `SMTP_PASS` | **QQ 邮箱授权码**（不是 QQ 密码） |

在 QQ 邮箱「设置 → 账户」里开启 SMTP 服务后生成授权码。**不配置也能正常运行**：所有干预和提醒照常出现在首页，只是不发邮件，并在邮件记录里注明“未配置 SMTP”。

没有检索服务时，择校工作台照常可用：AI 给出的候选里所有具体数字一律显示“待核实”，由服务端强制抹除，不依赖模型自觉；学生可以把官网链接贴进对话，平台读取页面正文（单页、不递归、拒绝本机与内网地址）后再回答。

## 关于“模拟模型”

还没有真实 API Key 时，把接口地址设为 `mock`（`.env` 或教师后台“模型与 Key”），平台会使用内置的模拟模型：

- 回复固定以“【模拟回复】”开头，对话页顶部显示“当前是模拟模型”的提示，**不会冒充真实 AI 的回答**；
- 它按选项协议输出“正文 + 末尾 json 代码块”，用来验证流式输出、选项解析、点选回传、额度扣减、调用留痕等整条链路；
- 测试学生 Key 时，Key 中含 `invalid` 会模拟“Key 无效”，含 `nobalance` 会模拟“余额不足”；
- 画像、择校候选、学习方案这类结构化输出也有对应的模拟数据，内容都带“【模拟】”字样，择校候选的院校名写作“【模拟·示例】某某高校”，不是真实院校。

拿到 tokenone 中转站的地址和平台 Key 后，在教师后台把接口地址改成真实地址、填入平台 Key、点“测试连通”即可切换，代码不用改。

## 对第8章数据表的补充

为实现第5章与第4章的要求，在第8章基础上补充了几个字段（都在 `schema.sql` 中用“补充”注明）：

- `users.class_id`：学生所属班级（由注册时的邀请码决定，用于区分真实班级与评委沙箱）；
- `users.use_own_key_basic`：第5.3节“基础模块也用我的 Key”偏好；
- `messages.agent_key`：该条回复使用的导师（请求发出时冻结）；
- `knowledge_report_picks`（阶段5，新表）：考核用知识库报告里学生自己挑的精选条目；
- `lab_agents`（阶段6，新表）：API 实验室“我的小智能体”（第六章课堂任务要求保存，第8章未列此表）；
- `users.expires_at`、`users.demo_note`（阶段8）：评委测试账号的有效期与备注；
- `mentor_docs.level`（阶段8）：资料的证据等级，引用时显示。

阶段8起已有数据库会在启动时自动补这些列（`server/src/db.js` 的 `migrate()`，可重复执行）。导师草稿用 `mentor_versions` 里 `published_at` 为空的那一行表示；资料是否进入某个版本记在该版本角色卡的 `doc_ids` 里，所以回滚能连资料一起恢复。

### 关于思考模式（`LLM_THINKING`）

`deepseek-v4.1-flash` 是推理模型：回答前会先输出一段隐藏的思考内容，这段内容也计入 token。如果让它思考，聊天要等十几秒才开始出字，而且 `max_tokens` 给小了正文会是空的。所以平台默认**关闭思考**（`LLM_THINKING=auto` 时按关闭处理，请求里带 `reasoning_effort:"none"` 和 `thinking:{type:"disabled"}`）：

| 值 | 效果 |
|---|---|
| `auto`（默认） | 关闭思考。回复快、省 token，图像与方案这类结构化输出也更稳定 |
| `off` | 强制关闭（同上，语义更明确） |
| `on` | 打开思考，学生能看到更“深思”的回答，但慢很多、更费 token |

如果以后换上非推理模型，这个参数不会造成影响——多传的字段会被中转站忽略。
